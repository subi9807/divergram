- 동일 감사 명령을 `.github/workflows/validate-services.yml`의 앱 검증 단계에 추가했습니다.

## 1. 검사 방법

```bash
cd app
npm run audit:i18n
```

감사 스크립트는 다음 항목을 자동 검사합니다.

1. 네 언어 JSON의 전체 중첩 키를 평탄화해 비교
2. 언어별 누락 키와 빈 값 검사
3. `{{count}}` 같은 보간 변수 불일치 검사
4. 비한국어 파일에 남은 한글 검사
5. 일본어·중국어 값이 영어 값과 동일한 항목 검사
6. `t()`, `tx()`, `i18n.t()` 밖에 존재하는 한글 문자열과 JSX 텍스트 검사

상세 원본 결과는 `app/i18n-audit.json`에 생성됩니다.

## 2. locale JSON 비교 결과

| 검사 항목 | 한국어 | 영어 | 일본어 | 중국어 |
|---|---:|---:|---:|---:|
| 전체 번역 키 | 894 | 894 | 894 | 894 |
| 누락 키 | 0 | 0 | 0 | 0 |
| 빈 값 | 0 | 0 | 0 | 0 |
| 보간 변수 불일치 | 0 | 0 | 0 | 0 |
| 영어와 동일한 영문 값 | 기준 | 기준 | 19 | 191 |

### 판정

- **구조 완전성은 양호**합니다. 네 파일의 키 구조, 빈 값, 변수 형식은 일치합니다.
- **중국어 번역은 미완료**입니다. 191개 값이 영어와 동일합니다. 인증, BLE, 장비, 탐색, 홈, 알림, 권한, 설정 등 실제 화면 문구가 포함됩니다.
- 일본어의 동일 값 19개에는 `Divergram`, `PADI`, `USD`, `bar`, `psi`, `English`, 이메일 예시처럼 번역하지 않는 것이 자연스러운 값이 다수 포함됩니다. 다만 `buttonHint`, `buttonLabel` 등은 문맥 검수가 필요합니다.
- 영어·일본어·중국어에 남은 `settingsPage.languages.ko = 한국어`는 언어 선택 화면에서 언어 고유 명칭을 보여주기 위한 의도된 값입니다.

### 중국어 우선 번역 영역

1. `auth.*`: 로그인, 가입, OAuth 오류와 안내
2. `permissions.*`: 위치·알림·Bluetooth 권한
3. `devices.*`, `ble.*`: 다이빙 컴퓨터 연결
4. `home.*`, `explore.*`, `reels.*`: 주요 사용자 화면
5. `settings.*`: 설정과 로그아웃
6. `notifications.*`: 다이빙 알림
7. `api.*`: API 데이터 기본 표시 문구

## 3. 소스 고정 텍스트 분석

### 전체 결과

- 번역 함수 안의 한글 기본값: 508개
- 번역 함수 밖의 한글 문자열 후보: **1,556개**, 55개 파일
- `defaultValue: '한국어'`는 번역 키 조회 실패 시에만 사용되므로 정상적인 안전 기본값입니다.
- 번역 함수 밖의 1,556개는 모두 오류는 아니며 정책 원문, 인증명, 스탬프 카탈로그, API 내부 메시지도 포함합니다. 그러나 사용자 화면에 직접 노출되는 항목은 다국어 전환 대상입니다.

### 별도 관리가 필요한 항목

- `src/legal/policyCatalog.ts`: 앱 내장 약관 원문이므로 일반 UI locale과 분리된 정책 locale 구조를 유지합니다.

- 브랜드, 단체명, 단위, URL, 이메일 예시는 다른 언어와 동일해도 정상일 수 있습니다.
- 로그·오류 코드·개발자 진단 문자열은 사용자 노출 여부를 확인한 뒤 번역 여부를 결정합니다.

## 4. 권장 작업 순서

1. 중국어 `191개` 동일 영문 항목을 실제 중국어로 번역
2. 로그인·설정·지도처럼 실패 상황에 노출되는 고정 문구를 locale 키로 이전
3. 프로필·교육·리조트·릴스의 정상 사용자 화면 문구 이전
4. 공용 컴포넌트와 시간 형식 이전
5. DiveLog, 라이선스, 관리자 화면 이전
6. CI에서 `npm run audit:i18n`을 실행해 누락 키·빈 값·변수 불일치를 차단
7. 네 언어별 핵심 사용자 흐름 스크린샷 테스트 수행

## 5. 완료 기준

- 모든 locale 키 수가 동일하고 누락·빈 값·변수 불일치가 0
- 중국어의 영어 동일 항목은 승인된 브랜드·단위만 남음
- 사용자 노출 가능 고정 한국어가 0
- 로그인 → 피드 → 검색 → 로그 작성 → 지도 → 리조트 → 프로필 → 설정 → 약관 흐름을 네 언어로 확인

## 6. 2026-08-13 적용 상태

- 비한국어 언어의 누락 키 fallback을 한국어가 아닌 영어로 변경했습니다.
- 비한국어 화면에서 `t()`의 한국어 `defaultValue`를 사용하지 않도록 공통 i18n 계층에서 차단했습니다.
- 로그인 화면의 OAuth 오류와 SNS 미설정 안내 12개를 네 언어 정식 키로 이전했습니다.
- 로그인 화면의 번역 함수 밖 한글 후보는 0개입니다.
- 남은 고정 한글 후보는 1,544개이며, 내부 상태값·정책 원문·화면 표시값이 섞여 있으므로 화면 단위로 ID와 라벨을 분리해 이전해야 합니다.
- 현재 상태를 “전체 완료”로 판단하지 않습니다. 다른 언어에서 한글 노출 0을 달성하려면 아래 순서의 화면 이전이 계속 필요합니다.
