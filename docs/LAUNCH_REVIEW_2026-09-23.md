# Divergram 출시 전 UX·운영 점검

이번 작업은 기존 기능을 유지하면서 관리자/앱 공통 UI, 주요 사용자 흐름, 외부 연동 운영을 개선한다. 문서의 상태는 소스·테스트·배포·실기기 검증을 구분한다.

## 현재 결과

- **관리자·API: 운영 배포 완료.** https://adm.divergram.com/ 에서 확인할 수 있다. 기존 화면과 기능을 유지하면서 공통 UI를 개편했다.
- **앱: 소스 수정·TypeScript·정적 검사·단위 테스트·iOS/Android JS 번들 생성 완료.** 이번 변경의 서명된 IPA/AAB 생성, OTA 발행, TestFlight/Play 배포, 스토어 제출은 하지 않았다.
- 전체 서비스의 모든 결함이 없음을 보증하는 단계는 아니다. 외부 계정·기기·정책 결정이 필요한 출시 조건을 아래에 구분했다.

| 해양 정보 | 키/조회 실패 시 샘플 수치가 실제 정보처럼 표시될 가능성 | 임의 수치 제거, 데이터 없음/낮은 신뢰 명시. 시정 값도 임의 추정하지 않음 |
| 해양 API | 앱에서 제공자 직접 호출·키 사용 | 인증된 서버 프록시, 위치 검증, 타임아웃·호출 제한·캐시. 실제 운영키 필요 |
| 앱 메뉴 | 접근성 버튼과 실제 터치 대상이 분리됨, 드래그 카드 이중 그림자 | 버튼 의미를 터치 대상에 배치, 키보드/스크린리더 활성화, 안전 여백. 메뉴 재정렬 기능 유지 |
| 알림 성능 | 작성자 몇 명을 표시하려고 전체 프로필 조회 | 해당 알림의 작성자 ID만 조회, 모두 읽음은 5개씩 제한 |

변경 UI 문구는 한국어·영어·일본어·중국어에 함께 추가했다. 공통 UI 변경은 Screen/Button/Card/EmptyState/탭 헤더에 적용하고, 피드·알림·멤버십 흐름은 별도로 보완했다. 기존 로그인 제공자·AdMob·푸시·메뉴 재정렬 기능은 제거하지 않았다.

Android 취소 후 잔여 이용 기간 처리는 [Google Play 구독 생명주기 공식 문서](https://developer.android.com/google/play/billing/lifecycle/subscriptions#cancellations)의 취소 상태와 만료 시각 기준을 확인했다. iOS 자동 갱신 여부는 현재 거래 조회로 확정할 수 없으므로 새 운영 화면에서 임의로 활성 표시하지 않는다.

## 새 운영 메뉴의 위치

- **운영 홈 → 운영 대시보드:** 핵심 지표, 지금 처리할 업무, 외부 API 상태 필터 및 해당 서비스 설정으로 이동.
- **시스템 관리 → API 관리:** 19개 서비스 그룹의 키·식별자·주소·활성 상태 관리. 비밀키 전체 마스킹, 빈 비밀키는 보존, URL/포트/JSON 검증, 암호화 실패 시 저장 차단, 미저장 편집 이탈 확인. DB/JWT/관리자 인증/암호화 루트 키는 웹 편집 대상에서 제외한다.
- **시스템 관리 → 운영 상태:** 작업·토큰·알림·신고 상태와 최근 7일 결제 단계별 이벤트. 실패한 조회는 정상 0건으로 표시하지 않는다.
- **파트너·수익 → 인앱 구독:** 저장된 구독 상태·이용 기간·자동 갱신 설정·검증 이력 확인. 읽기 전용이며 결제·환불 버튼은 없다. 마지막 검증 정보임을 명시한다.

API 관리의 모든 항목이 저장 즉시 모바일에 적용되는 것은 아니다. 서버 요청 시 읽는 설정과 연결 객체 재초기화/작업 서버 갱신이 필요한 설정, 앱 환경 반영 및 재빌드가 필요한 설정을 구분해야 한다. 외부 서비스 진단의 `설정됨`은 실제 전송·결제 성공을 뜻하지 않는다.

## 추가 정보 또는 실제 환경에서 필요한 검증

- iOS TestFlight/Android Play 테스트 설치와 결제 가능한 테스트 계정: 실제 구매·복원·취소·만료·서버 검증까지 확인 필요. 설정/단위 테스트만으로 실제 구매 성공을 보증할 수 없다.
- Stormglass 운영키, 실제 데이터 제공 범위/예산. Cloudinary는 사용자 요청대로 보류하며 자체 업로드를 유지한다.
- Instagram/Threads/Naver/Kakao 승인된 앱 ID, 콜백 URL, 제공자 심사 상태. 기존 설정 확인과 외부 제공자 승인은 별도이다.
- Garmin/Suunto/Shearwater 계약·승인·장비와 실제 로그 프로토콜 검증. 검증되지 않은 연동을 완료로 표시하지 않는다.
- 관리자 역할별 최종 권한표, 삭제/보존 기간, 장애 알림 수신자, 백업 복구 목표. 정책 판단은 사용자 확인이 필요하다.
- 실기기에서 큰 글자, VoiceOver/TalkBack, 백그라운드 푸시, 저속/오프라인, 업로드 중 앱 종료, 계정 전환, 카메라/사진 권한 확인.
- 스토어 최종 제출과 공개 일정. 테스트 완료 전 출시 준비 완료로 판정하지 않는다.

## 출시 전 남은 우선순위

| 우선순위 | 항목 | 현재 판단 / 필요한 조치 |
| --- | --- | --- |
| P0 | iOS·Android 실제 구매/복원/취소/만료 | 진단 코드·오류 재시도는 반영. 각 스토어 테스트 계정과 실제 설치 기기에서 서버 검증·권한 부여까지 확인해야 한다. 사용자의 실결제는 실행하지 않음 |
| P0 | 구독 갱신·환불·철회 자동 반영 | 현재 확인한 서버는 앱 구매/복원 시 검증 경로가 중심이다. App Store Server Notifications/Google RTDN 수신 경로는 저장소에서 확인되지 않았다. 스토어 콘솔 통보 설정·Pub/Sub 권한·서명 검증·중복 이벤트 처리까지 별도 구현 및 종단 테스트 필요. 구독 운영 화면은 이 제한을 명시함 |
| P0 | 양 플랫폼 회원가입 및 약관 동기화 회귀 | 기존 자동 테스트 통과. 실제 SNS별 로그인/신규 가입/재설치/기존 앱 호환은 테스트 계정으로 재확인 필요 |
| P0 | 푸시·딥링크·업로드 실기기 회귀 | 앱 종료/백그라운드·권한 거절·오프라인·중복 클릭·네트워크 복구·계정 전환 확인. 기존 승인된 푸시 체크리스트 유지 |
| P1 | 해양 정보 제공 | 서버 프록시 준비됨. Stormglass 운영키·쿼터 확인 후 실제 위치 데이터와 결측 화면 검증. 다이빙 판단을 대신하는 정보로 표시하지 않음 |
| P1 | 외부 SNS·장비 연동 | 제공자 승인/콜백/권한과 장비 프로토콜·실장비가 필요. 기존 기능 보존, 승인 없이 기능 제거 또는 완료 표시하지 않음 |
| P1 | 운영 권한·보존·복구 정책 | 관리자 역할 권한표, 개인정보 보존/삭제 기간, 감사로그 보존, 장애 알림 담당자, 복구 목표 확정 후 구현 범위 결정 |
| P2 | 사용하지 않는 레거시 코드 | `app/src/features/dive/DiveMode.tsx`에 위치 이력 저장 TODO가 남아 있으나 활성 화면 참조는 확인되지 않음. 활성 다이빙 로그와 구분하고 재사용 전 검토 |

Cloudinary 유료 도입은 기존 사용자 결정대로 **보류**한다. SMS·푸시 대량 발송, 실결제, 미디어 공개 게시, 새 유료 서비스 가입은 이번 작업에서 실행하지 않았다.

## 검증 기록

- 수정 전 기준: API 136개, 앱 88개 테스트 통과; 앱 TypeScript 통과.
- 최종 API 단위 테스트 **145/145**, 앱 **90/90** 통과. 디자인의 모서리 반경 변경에 맞춰 기하 테스트 기대값도 22 → 18로 갱신했다.
- `npx tsc --noEmit`, `npx eslint app src` 통과. 관리자 Vite 프로덕션 빌드 성공.
- iOS·Android Hermes JS 번들 생성 성공. 이것은 서명된 앱 패키지 빌드 또는 실기기 실행 성공과 다르다. 로컬 iOS 시뮬레이터는 Xcode 라이선스 미승인으로 실행하지 않았고 약관에 대신 동의하지 않았다.
- 격리된 샘플 데이터로 관리자 **26개 화면** 기본 표시, 모바일 가로 넘침, 메뉴 검색, 상태 조회 실패 중 설정 편집, 미저장 편집 보호, 저장 후 상태 검증 통과. API 저장 테스트는 샘플에만 수행.
- 앱 웹 렌더러 390×844에서 피드·메뉴→알림 이동·읽지 않음 필터 검증, 스크린샷 확인. 실제 iOS/Android 실기기 화면으로 간주하지 않는다.
- 운영 서버 관리자 조회 API **19개**와 공개 관리자 HTML/JS/CSS 200 응답 확인. API 키 필드의 비밀 원문 노출 0건, 비로그인 설정/해양 API 401, API/작업 서버/관리자 PM2 online 확인. 새 구독 조회 API도 200 응답이며 현재 저장된 구독·검증 이력은 0건이다. 이 결과만으로 과거 스토어 결제가 없었다고 단정하지 않는다.
